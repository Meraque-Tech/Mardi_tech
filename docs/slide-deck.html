Overview

Sensor Fusion & Bed Detection

Three ROS 2 services running on a Jetson Orin Nano turn a serial GNSS receiver, a BLE IMU, and a USB camera into a live, GPS-aware detection dashboard.

ROS 2 Humble TensorRT Docker Compose Jetson Orin Nano

The chain

Raw sensors to a live dashboard, in three services

Service 01
sensor_data_raw
Serial GNSS receiver + BLE IMU. Publishes raw position fixes and orientation data onto ROS topics.
→
Service 02
imu_gnss_raw
15-state error-state Kalman filter fuses GNSS + IMU into a smooth position, heading, and forward/backward motion state.
→
Service 03
yolov8-trt-bed-detect-orin
TensorRT camera detection, gated and geotagged by the fused motion state. Serves the web dashboard.

All three talk only over ROS 2 topics on the loopback DDS domain — no direct API coupling between containers.

Service 01

sensor_data_raw — the raw feed

Two nodes bridge physical hardware onto ROS topics: a serial JSON reader for the GNSS receiver, and a BLE driver for the IMU.

▸
/gnss/pvt — std_msgs/String, raw PVT JSON
▸
/receiver/fix — sensor_msgs/NavSatFix
▸
/imu/data_raw → /imu/data — sensor_msgs/Imu, via complementary filter

The GNSS receiver is pinned to a fixed device path (/dev/gnss_rtk) via a udev rule keyed to its physical USB port — so USB enumeration order can never swap it silently.

Service 02

imu_gnss_raw — the fusion core

A single node, gnss_imu_eskf_node, runs a 15-state error-state Kalman filter — position, velocity, orientation, and both IMU biases.

15
Filter states tracked
~100Hz
IMU strapdown prediction rate
100
Stationary samples for bias init
3
Motion states: idle / forward / backward

Publishes both a fused estimate and a raw-GNSS-only estimate side by side — useful for validating the filter against ground truth in the field.

Closing the loop

The dashboard talks back to the fusion node

The detection service doesn't just consume position data — it can retune the fusion filter live from the browser.

←
GNSS_FIX_TOPIC = /receiver/fix — dashboard lat/lon
←
MOTION_STATE_TOPIC = /gnss_imu_eskf/motion_state_raw_gnss — direction
←
GNSS_ONLY_ODOM_TOPIC = /gnss_imu_eskf/gnss_only_odom — auto-save distance gating
→
MOTION_POS_DEADBAND_TOPIC = /gnss_imu_eskf/motion_pos_deadband — dashboard writes back

Worth knowing

Documented drift between code and docs

Research for this documentation surfaced a few real discrepancies worth resolving, not just typos.

Engine path swap riskThe aarch64-mounted config defaults to the x86 engine file path — worth confirming which engine actually loads on the Orin.
Undeclared filter paramsSeveral tuning values in the ESKF's YAML aren't wired into the node's code and are silently ignored.
Stale IMU package READMEDescribes an older architecture with topic names that no longer match the deployed launch graph.
Hardware mismatch in READMEDetection package prerequisites describe Jetson Nano; the actual build targets Jetson Orin Nano.
