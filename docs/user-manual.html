User Manual

Bed Detection Dashboard

Everything you need to start the system, use the dashboard, and troubleshoot common issues on the vehicle's onboard Jetson computer.

1What it does

This system runs on the vehicle and combines a GNSS receiver, an IMU, and a camera to detect and count objects ("beds") while tracking the vehicle's motion and position.

Position & motionFuses GNSS and IMU readings into a smooth, reliable estimate of where the vehicle is and whether it's moving forward, backward, or idle.
Camera detectionRuns a camera-based detector that counts objects in view in real time.
Smart auto-saveOnly saves a snapshot when the vehicle is actually moving forward and has traveled far enough — no duplicate saves while parked or reversing.
Web dashboardStart or stop detection, view live counts, browse saved images, tune settings, and download QA reports from any browser.

2Starting the system

On the Jetson:

cd ~/Mardi_tech
./run_ai.sh

This detects the computer's architecture and starts all three required services together. It also stops any previously running containers first.

To check everything is up:

docker compose ps
docker compose logs -f imu_gnss_raw-aarch64

4Dashboard features

Live countCurrent detected object count per class, updated in real time.
Confidence / statusWhether a detection above the configured confidence threshold is currently in view.
Start / StopTurns the detector on or off. Detection does not run automatically on boot — check status before assuming it's running.
GNSS position & directionLive latitude/longitude and whether the vehicle is moving forward, backward, or idle, with a recent path trace.
Auto-save toggleAutomatically saves a snapshot (image + counts + position) when the vehicle moves forward past the configured distance since the last save.
Motion deadbandMinimum distance (meters) the vehicle must travel before auto-save considers it "new". Default 0.3 m, adjustable live.
Saved images galleryBrowse, download, or delete previously saved snapshots.
Model managementUpload new detection models, convert them, and switch which one is active — no restart needed.
QA reportDownloadable HTML report flagging low confidence, missing GNSS, near-duplicate positions, or long detection gaps.
ShutdownSafely powers off the physical Jetson from the dashboard.

5Typical workflow

  1. Power on the Jetson and confirm ./run_ai.sh has started all three services.
  2. Open the dashboard and confirm GNSS position is showing (valid indicator) and the camera preview is live.
  3. Press Start to begin detection.
  4. Enable Auto-save if you want the system to log snapshots automatically as the vehicle moves.
  5. Drive the route.
  6. When finished, press Stop, then use the Saved images gallery or Download report to review results.

6Cautions

⚠
Auto-save can fill storage quickly if left running continuously without a moving vehicle. Check the images gallery periodically and clear old data if storage is a concern.
⛔
Delete all data is destructive and cannot be undone. Only use it when you're certain you no longer need the saved images and history.
⚠
GNSS position must be valid before auto-save is meaningful. If the GNSS indicator is red or stale, position-based auto-save will not trigger correctly.
⚠
Don't move the GNSS receiver or camera to a different USB port without telling whoever manages the system config. The GNSS receiver is pinned to a specific physical port for reliable detection — moving it will break that until the configuration is updated.
⛔
Shutdown powers off the whole computer, not just the software. Use it only when you're finished with the session.
